# Changelog

## [Unreleased]

### Changed

- New setting `AutoAssignMixedChests` under `[Organize]` (default `true`, host-synced): after the threshold step, Organize gives each mixed chest below the threshold a category that is short of space. Set it to `false` to keep them as unassigned sources, as in 0.1.0. Put away inventory is unchanged.

### Added

- Compendium: press **Compendium** in the character menu for a spoiler-free, searchable, cross-linked wiki that fills in as you discover items, creatures, biomes and building pieces. It reads the game's own data, so other mods' additions are included.
- Character menu: a panel below the inventory with a live 3D view of your character. Helmet, chest, legs, cape, utility and trinket move into real slots and free their inventory spaces; weapon, shield and ammo slots show what is equipped. The panel hides while a chest is open.
- Quick put away: Shift + right-click an inventory stack to send it straight to the base's chests by category, with no preview.
- Put away selected: press **Put away selected** in the base menu, click inventory items to select them, and press it again to move only those into the base's chests by category. The button shows what its next press does and how many stacks are picked, **Cancel** clears the selection, and closing the menu or inventory cancels too. A selected stack moves even from the hotbar or the never list, and equipped items never move.
- Every panel the mod builds now uses the game's wood, with darker recesses for lists and fields. Favourite stars moved to the top-left of the slot so they no longer cover the stack count.
- Base menu: buttons are grouped by what they act on, and each chest's row shows icons of its most plentiful items with a thin fill bar.
- Base management: a window listing every base in the world, wherever you stand, with biome, chests, fullness and distance. Unnamed bases get a name automatically, and you can rename any of them.
- Move items between any two bases from **Base management**, wherever you stand: press **From** on one and **To** on another, read the preview and confirm. Items move into the destination's chests by category. Items the world's portal rule blocks stay where they are, and the preview and summary name them.

## [0.1.0] - 2026-10-29

### Added

- Hover text of a chest now shows one extra line with its base: `[In base: <N> stations]` or `[Not in a base]`, followed by the category or Keep when one is assigned, and a crafting station shows `[Base: <N> chests]`. The line is read from the cached base, so hovering does not search the base again.
- Organize base button and base status line on every crafting station panel in a base.
- Put away inventory button next to Organize base on every crafting station panel in a base, and the optional DepositKey hotkey (unbound by default): moves the inventory into the base's category chests, never the hotbar, equipped items, favourites or DepositNeverItems; DepositPreview shows a preview first, and every Put away ends with one summary line such as "Put away: 4 stacks moved, 2 no room".
- Base fill statistics: the status line on a crafting station panel now reads `Base: N stations, M chests, P% full`, where P is how many slots of the base's eligible chests hold an item, rounded to the nearest whole percent (`0% full` when the base has no eligible chest).
- Bases: a base is the crafting stations connected within build range (capped by `MaxBaseStations`) and the eligible chests near them; carts and ships are left out by `ExcludeVehicles`, and a base is reused for `BaseCacheSeconds` before it is searched again.
- Chest reservation adapter: reserves a chest through the vanilla open handshake (request, response, ownership) before any write, marks it in use for the duration and releases it; chests another player has open are reported in use with that player's name and never forced closed; the local owner, single-player and host paths reserve without a network round trip; the requester never sees the chest window open. Debug-only Shift+E probe for playtesting.
- Requirement display: the crafting panel requirement list and the build tooltip show the inventory plus the base chest amounts.
- Building from base chests: placing a piece with the hammer inside a base uses the materials in the base chests, taken all at once like crafting; with `CraftFromBase` off, building stays vanilla.
- Favourites: hold Alt and left-click an occupied inventory slot to toggle it as a mod favourite. A favourite slot shows an orange top-left marker, and the set is saved with the character (`basestorage.fav` in the custom data); vanilla ignores it when the mod is removed.
- Categories file: `BepInEx/config/BaseStorage.categories.txt` is written on first run with every vanilla item, is never overwritten, and falls back to item types for items it does not list.
- Chest category storage: a chest's category is stored on the chest's networked data under `basestorage.cat` (`k` for Keep, `c:<name>` for a category, no key or an empty value for Auto), so every player sees the same assignment and it survives restarts. Core defines the cycle Auto, each category in catalog order, Keep, forward and backward with wraparound, and reads a category the catalog no longer knows as Auto without touching the stored text. Every change goes through the chest reservation handshake: a chest another player has open, that denies access, that does not answer or that is gone is left unchanged and the player is told why (`Chest category not changed: ...`).
- Category button on the open-chest panel: a vanilla-style button next to Take All / Stack All shows the chest's current category and cycles it (left-click forward, right-click back) through Auto, every category of the categories file, and Keep; it greys out while a change is waiting for the chest owner. The optional `CycleCategoryKey` hotkey (under `[Keys]`, unbound by default) cycles the chest you are looking at while no menu is open.
- Organize runs in game: the `OrganizeKey` hotkey (unbound by default) starts an Organize for the base you stand in, or shows `Not in a base`. The base is snapshotted and planned once, a confirm popup shows the preview (`OrganizeSkipPreview` skips it), the base lock on the lowest-id station refuses a second player with `Organize in progress by <name>`, the moves run at most `MovesPerFrame` per frame through the chest reservation handshake, and every run ends with one top-left summary line and one Info log line (for example `Organized 6 stacks; 1 chest skipped (in use by Erik); 2 stacks had no room`, with `stopped early: <reason>` when a chest refused, changed, filled up or the lock was lost).
- The Organize preview now reads `Organize base: <N> stacks to move across <M> chests.` followed by one sentence per claimed category, the stacks with no room and the skipped chests grouped by reason (in-use chests name the player), and a finished Organize ends in one line such as `Organized 214 stacks; 1 chest skipped (in use by Erik); 4 stacks had no room`. Every word comes from the strings table.
- Version handshake: on every connection both sides send their BaseStorage version over the `BaseStorage_Version` RPC. With `RequireSameVersion` on (the default) the host refuses a friend with a different version, or without the mod after 5 seconds, through the vanilla incompatible-version error, and both sides read `BaseStorage version mismatch: host X, you Y` (the host as a notice, the friend under the vanilla error text; a friend without the mod sees the vanilla screen only). A friend whose own version differs from the host leaves on their own with the same text. Single-player and the host's own session send nothing. One Info log line per outcome, `Version handshake: peer <id> ...`.
- Host-synced settings: in multiplayer the host's synced settings and category file apply for the session; the friend's own files are untouched, and single-player is unaffected.
- Settings and logging: 18 settings in 5 sections of `dawso.valheim.basestorage.cfg`, hotkeys unbound by default, one Info line when the settings load, and Debug detail behind `DebugLogging`.
- Crafting from base chests: at a crafting station inside a base, crafting an item, upgrading an item and crafting several at once (hold Left Shift) count the materials in the base chests as well as the inventory, and take them all at once before the item is made, the inventory first and then the nearest chests. An upgrade needs the amounts for the quality it upgrades to, and crafting several at once needs the per-craft amounts times the number crafted. If a chest cannot be reserved or its contents changed, nothing is taken, the item is not made or upgraded, and `Materials moved, try again` is shown. With `CraftFromBase` off, crafting stays vanilla.
- Console command `dons-qol organize`: in the in-game console (start Valheim with `-console`, press F5) it starts an Organize for the base you stand in, with the same preview, lock and summary as the Organize base button; outside a base it prints `Not in a base`, and while another player organizes the base it prints `Organize in progress by <name>`.
### Developer

- Opt-in Thunderstore package: `dotnet build -c Release -p:PackageThunderstore=true` writes `dist/BaseStorage-<version>.zip` (manifest.json, icon.png, README.md, CHANGELOG.md, plugins/BaseStorage.dll and plugins/BaseStorage.Core.dll). Plain builds and the gates never produce it.
- Developer README at the repo root: prerequisites, `VALHEIM_DIR` setup, the gate commands, the patch-target contract tests and how to re-run them after a game update, deploy-to-game and Thunderstore package commands, and how to read the BepInEx log.
- Core version handshake (`BaseStorage.Core.Networking`): `ModVersion.Current` from `Version.props` at build time, `VersionHandshake` payload `BSV1;<version>` (string and ASCII bytes, malformed decodes to null), `VersionCheck` accept/reject decision honouring `RequireSameVersion`, and `VersionCheckResult.FormatMessage` for the "BaseStorage version mismatch: host X, you Y" notice. No RPC yet (S-E006-002).
- Core host-sync payload (`BaseStorage.Core.HostSync`): `HostSyncPayload.Capture` gathers every host-synced section 7 setting plus the host's category file text (CRLF normalised to LF), `HostSyncCodec` encodes it as `BSC1;KEY=VALUE ... @LENGTH TEXT` text or UTF-8 bytes and decodes only canonical payloads (anything malformed gives null, 1 MiB cap), and `LayeredSettingsSource` answers host-synced keys from the applied payload while connected as a client and from local settings otherwise, leaving the active layer unchanged when a payload is rejected. No RPC or Plugin wiring yet (S-E006-002, S-E006-004).
- Core Deposit planner (`BaseStorage.Core.Organize.Deposit`): plans a "Put away inventory" with the player inventory as the only source and the base's category chests as destinations, using the Organize planner's own fill (merge first, then empty slots, then claimed overflow chests). The hotbar row, equipped items, mod favourites, anything on `DepositNeverItems` (default `@food,@mead,@ammo,Hammer,Hoe,Cultivator,FishingRod,@bait`), stacks of the same item as an excluded stack and stacks above their max stack are never moved. No button or hotkey yet (S-E004-015).
- Quality audit: Core line coverage is measured with the command in the README (98.68% at audit time), a test reads the built plugin and fails if an Update or LateUpdate calls the base resolver, the cache rebuild or a planner directly, and a test checks that this CHANGELOG, the package README and docs/PLAYTEST.md describe the same features.
